Product strategy — why Copilot is the competitive moat

PHASE 3 — INTELLIGENCE & MOAT
Copilot is built last on purpose. It needs real customer data from all other modules before it can be useful. Once it has that data, it becomes the hardest thing for competitors to replicate — because they'd need your data volume and your graph depth, not just the LLM.
RETENTION DRIVER
The platform's target for Phase 3 is NRR > 120%. Copilot is explicitly called the "moat feature" — the one that makes customers unwilling to switch because it gets smarter the longer they use it. Their question history, their custom rules, their posture trends all make the answers better over time.
SIGNATURE FEATURE
The UI spec explicitly calls this "CloudVisor's signature feature — make it feel premium." It's the only page in the product with special design language: chat-style layout, token streaming, embedded rich results, and the "Powered by Claude AI" label in the page header.
PERSONA MULTIPLIER
It serves every user persona differently without requiring separate views. A CISO asks "What's our compliance posture?" A SOC analyst asks "Show me active threats." A DevOps engineer asks "Generate a Terraform fix for this finding." Same endpoint, different intents, different retrievals.

How Copilot interacts with every other service

READS VIA HTTP
Graph Service (port 8001)
Fetches asset inventory, graph neighbors, attack paths, and executes read-only Cypher queries for IAM traversal. The deepest retrieval source — used by THREAT and POSTURE intents.
READS VIA HTTP
Alert Service (port 8004)
Fetches findings by severity/status/provider, finding stats, and incident context. Used by FINDING, POSTURE, and THREAT intents. Elasticsearch full-text search under the hood.
READS VIA HTTP
Policy Service (port 8003)
Fetches compliance summary per framework, per-control pass/fail, and control evidence artifacts. The primary source for COMPLIANCE intent queries and report generation.
READS VIA HTTP
Auth Service (port 8002)
Validates every incoming JWT. Organization ID extracted from token drives RLS context for all downstream DB queries. No copilot query ever runs without auth validation.
READS + WRITES
PostgreSQL (copilot schema)
Writes every query + response to copilot_queries (append-only audit log). Reads query history for the GET /history endpoint. RLS enforced on both.
PRODUCES
Kafka (copilot.query_logged)
Emits a structured event after every query for audit purposes and downstream analytics. Topic consumed by alert service for audit.events correlation. Planned consumer: finding.created for context updates.
CALLS EXTERNAL API
Anthropic Claude API (claude-sonnet-4-6) + multi-provider fallback
The LLM provider factory selects the active provider via the COPILOT_LLM_PROVIDER env var. Primary: Anthropic (claude-sonnet-4-6). Fallbacks: Google Gemini Flash Lite, OpenRouter (gemma-4-31b-it), local Ollama (qwen2.5). OpenAI is declared but raises NotImplementedError. The factory pattern means swapping providers requires zero code changes.

Query execution walkthroughs — how each intent resolves

Which production workloads have critical CVEs and are internet-facing?
1 Intent → THREAT
2 Graph Service: fetch assets where is_internet_exposed=true AND environment=prod
3 Alert Service: fetch findings where severity=CRITICAL AND status=open, correlate by resource_id
4 AIOps Priority Score used to rank results — highest EPSS + KEV workloads surfaced first
5 Claude synthesizes: "I found 3 production workloads matching your query. payments-api (CVE-2024-1234, EPSS: 0.94) is most likely to be exploited."
Show me all IAM roles that can access our payments RDS database
1 Intent → THREAT
2 Graph Service Cypher: MATCH (r:Asset)-[:HAS_ACCESS_TO]->(db:Asset {name:'payments'}) WHERE db.resource_type='RDSInstance' RETURN r
3 Graph traversal also looks for cross-account [:ASSUMES] edges to catch lateral movement paths
4 Claude returns a table of role names, associated accounts, access type, and whether any role has excessive permissions
Generate a SOC 2 Type II evidence report for our logging controls
1 Intent → COMPLIANCE
2 Policy Service: fetch GET /policy/compliance/soc2 — per-control pass/fail
3 Policy Service: fetch GET /policy/compliance/soc2/evidence — CloudTrail enabled, VPC Flow Logs, audit log retention configs
4 Claude formats into structured evidence report: control ID, description, status, evidence artifacts, remediation for failures
5 UI offers "Open as PDF report" button — saves response as downloadable audit artifact
What changed in our AWS environment in the last 24 hours?
1 Intent → DRIFT
2 Audit log: fetch user + system actions in the last 24h for this org
3 Graph Service: GET /internal/assets/{id}/history for recently changed assets — diff_from_previous JSONB field
4 CSPM snapshots: compare today's posture_score vs yesterday's baseline
5 Claude produces a change summary: new resources, deleted resources, config changes, new findings created, posture score delta

Copilot × AIOps Priority Score — how findings are ranked in answers

When the copilot returns findings in a THREAT or FINDING intent response, it sorts them by the AIOps-computed Priority Score (0–100) written by the aiops service. This means copilot answers are already risk-prioritized — the finding most likely to be exploited appears first, not just the most recent or highest CVSS.

Compliance frameworks Copilot can report on

CIS Benchmarks
CIS AWS v1.5, CIS Azure v2.0, CIS GCP v1.3. Per-control pass/fail with evidence artifacts and remediation steps.
SOC 2 Type I / II
CC-series trust service criteria. Evidence report generation for logging, access, encryption, and availability controls.
PCI-DSS
Cardholder data environment scoping, network segmentation controls, encryption at rest/transit. CDE map via DSPM data stores.
HIPAA
PHI access controls, audit logging, encryption requirements. Maps to DSPM-discovered data stores containing health data.
GDPR Article 30
Processing activity register generated from DSPM-discovered data stores. Data residency and transfer controls.
ISO 27001 + NIST CSF
Control mapping across all security modules. Gap analysis and risk register exports. Annex A control coverage.

Database schema — copilot_queries table

Column Type Notes
id PK UUID gen_random_uuid()
organization_id FK UUID RLS enforced — tenant isolation. References organizations(id)
user_id FK UUID The user who sent the query. References users(id)
query TEXT The original natural language question
intent TEXT Classified intent: POSTURE | FINDING | COMPLIANCE | REMEDIATION | THREAT | DRIFT | GENERAL ⚠ GENERAL missing from DB CHECK constraint — will fail
response TEXT Full LLM response text
citations JSONB Structured citations: finding IDs, asset IDs, rule IDs. Currently always [] — parser not yet implemented
model_used TEXT The LLM model string used (e.g. claude-sonnet-4-6)
latency_ms INT Total end-to-end query latency in milliseconds
created_at TIMESTAMPTZ Append-only. No updates, no deletes ever issued against this table.

Implementation status — what's done vs what's next

RAG pipeline skeleton done
6-step pipeline wired: intent classification → retrieval → prompt construction → LLM call → response. All 7 intents classified. Multi-provider factory complete.
Multi-provider LLM factory done
Anthropic (primary), Gemini, OpenRouter, Ollama all implemented. Provider selected by env var at startup. Adding a new provider requires one new class file.
Multi-source retrieval (graph + findings + compliance + audit) done
All 4 retrieval sources implemented and called in parallel. Intent routing determines which sources activate. RLS enforced on all DB reads.
Query history endpoint + audit table done
copilot_queries table with RLS. GET /v1/copilot/history returns paginated history. Append-only — no deletes, no updates.
Streaming response (token-by-token) partial
Anthropic streaming is implemented in the provider. The API endpoint supports streaming mode via request flag. Audit logging during streaming (write to DB while tokens arrive) is not yet implemented.
Fix GENERAL intent DB constraint blocker
The copilot_queries.intent CHECK constraint does not include 'GENERAL'. Any query classified as GENERAL will fail to insert into the audit log. Must add GENERAL to the constraint before launch.
Implement _format_asset_snapshots() blocker
Missing from prompt_builder.py. DRIFT intent queries call this function and will throw AttributeError at runtime. The CSPM snapshot retrieval path exists but the formatter is not implemented.
Citation parser todo
Parse LLM response to extract structured source references (finding IDs, asset IDs, rule IDs). Currently always returns []. Required for UI "cited sources" feature and for audit completeness.
Vector store integration (step 2 of RAG) todo
Query embedding + semantic similarity retrieval is commented out. Needs a vector store (pgvector, Pinecone, or Weaviate) and an embedding model. This will significantly improve retrieval quality for vague or ambiguous queries.
Kafka consumer — finding.created todo
Subscribe to finding.created to proactively update retrieval context caches. Allows copilot to surface "you have a new critical finding" context without the user asking. Marked as TODO in the Kafka topic registry.
Auto-remediation PR workflow todo
GitHub / GitLab integration to open PRs with LLM-generated Terraform fixes. Requires OAuth token per org stored in Vault. Tracking: PR opened → merged → finding resolved.
Test suite todo
Test directories are empty. Needs: unit tests for intent classifier, prompt builder, each retriever, provider factory. Integration tests with mocked LLM, real DB + Kafka. Target: 80%+ line coverage before shipping.

Observability requirements

Like every CloudVisor service, the copilot must emit structured JSON logs to stdout with correlation_id, organization_id, service_name, and level on every log line. Prometheus metrics must be exposed at /metrics. OpenTelemetry traces must wrap all inbound HTTP requests and outbound Kafka publishes.
copilot_queries_total (counter) copilot_query_latency_ms (histogram) copilot_intent_distribution (counter by intent) copilot_llm_provider (label) copilot_retrieval_latency_ms (by source) copilot_errors_total (by error type)
